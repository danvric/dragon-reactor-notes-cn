## DRAGON 是啥

- 一个算核反应堆燃料块的电脑软件。
- 作用：
  1. 看燃料块里面**中子**的运动；
  2. 燃料慢慢烧完会发生什么。
- DRAGON 只算一个栅元（CANDU 对应一根燃料棒束的二维横截面那一小块），算完打包成少群截面数据库，交给 DONJON 再去算整个反应堆。
- 工作模式：没有 GUI，纯敲代码。
  - 要你写一份指令，软件按顺序一条条干活。

> DONJON 能把所有数据拼起来，组成整个反应堆的结果。

## 核心底层逻辑（必须懂）

- 三个主要性质：

1. **分工干活**：拆成一堆独立小工具（module）。每个小工具只干一件事。你排好顺序，一个干完交给下一个。
2. **盒子传数据**：工具之间不能直接聊天。所有计算出来的数字，全部塞进虚拟盒子（数据结构）。前一个工具算完把结果放进盒子，后一个工具打开盒子拿数据。
   > 为什么？——盒子可以放内存（跑得快），也可以存硬盘文件（省内存）。
3. **全部干完写一句 END，程序停止。**

> 类比：流水线。盒子就是流水线的周转筐，每个工位只做自己那一步，筐子往下传。

- 盒子的真名对照（混个脸熟）：

| 盒子名 | 里面装什么 |
| --- | --- |
| microlib | 材料库：每种材料有啥原子、跟中子怎么反应 |
| macrolib | 合并后的材料数据（从 microlib 加工出来） |
| geometry | 画好的几何模型 |
| tracking | 扫描模型量出来的体积、路径长度 |
| asmpij | 组装好的中子转移概率矩阵 |
| fluxunk | 中子通量、keff 等计算结果 |
| edition | 均匀化压缩后的最终输出 |
| burnup | 燃耗结果 |

## 一共就 5 大步骤，所有计算逃不开这个流水线顺序

- 预览：**备料 → 画几何模型、扫描模型 → 算中子行为（主要） → 加工输出结果 → 输出**

### 步骤 1：备料（准备所有材料数据）

对应原文档 LIB: 和 MAC: 模块（第 3.1、3.2 节）。

1. 读现成数据库：里面存了各种原子碰到中子会发生什么反应。这些数据也叫**截面**——就是"中子撞上一个原子的命中面积"，面积越大越容易反应，这里的面积不等于原子真实面积。
2. 定义每一种材料（比如燃料、外壳、冷却水）：写明里面有哪些原子（同位素）、每种原子有多少个（单位体积里的原子颗数）、材料有多热（温度越高，原子越容易抓中子的"共振峰"，中子会消失更多）。
3. 如果要看燃料烧掉后变什么：写明哪些原子烧掉之后会变出什么新原子。

- 两条路二选一：
  - **LIB:** 读官方核数据库，自己按配方混材料（常规做法）；
  - **MAC:** 跳过数据库，直接把算好的材料数据手写进指令文件（做简单测试用）。

> 就像做饭，把所有食材按配比配好。

### 可选工序（步骤 1.5）：共振自屏蔽

对应第 4 章，SHI: / TONE: / USS: / AUTO: 模块。

- 干嘛的：铀-238 这类原子在个别能量段特别爱抓中子（叫"共振"）。但数据库里的数值是按"材料完全均匀摊开"的假设得到的；真实燃料是实心块，共振能量的中子还没走到燃料内部就被表层原子核吸收，燃料内部该能段中子变少，整体实际共振吸收会和均匀假设不一样。这个工序就是修正这部分核截面数据。
  - 就是计算上被吸收的中子。
- 什么时候用：正经计算基本都要做，插在备料和算中子之间；纯宏观截面测试可以跳过。
- 四个模块是四种算法，精度和速度不同，见文末速查表。

### 步骤 2：画模型（画出燃料块长啥样）

对应原文档 GEO: 模块（第 3.3 节）。

1. 画形状：方块、六角格子、圆筒，随便选，反应堆长啥样就画啥样。
2. 给每一块区域分配上面步骤 1 准备好的材料：哪一块是燃料，哪一块是水，哪一块金属壳。
3. 设置边界规则：
   - 无限复制：这块燃料外面，无限重复一模一样的燃料块；
   - 完全开放：中子跑出去就再也回不来。

> 相当于 CAD 画图，只画我们要研究的那一小块反应堆。

### 步骤 3：扫描模型（给电脑算几何）

对应原文档各种 TRACK 追踪模块（第 3.6 节）。

- 画完图电脑看不懂。这个工具虚拟发射大量射线扫一遍整个模型。
- 输出：每个小块体积多大、表面积多大、射线穿过各个部分的路径长度，全部存进盒子。
- 书里有 8 种扫描器，干的活一样，区别是适用的几何形状和精度速度。常用的三个：EXCELT:（2D/3D 标准）、NXT:（燃料棒簇）、MCCGT:（新算法，更准）。怎么选见速查表。

### 步骤 4：算中子行为（核心计算）

分 2 小步：

- **4-A ASM: 工具**（第 3.7 节）：拿扫描出来的几何数据 + 材料反应数据，组装中子输运求解需要的系数 / 碰撞概率矩阵。
- **4-B FLU: 工具**（第 3.8 节）：用上一步概率，大规模计算：
  - 中子到处飞的多少（通量）
  - 链式反应能不能自我维持（keff：等于 1 正好维持，大于 1 越来越猛，小于 1 慢慢熄灭）
  - 中子从边界跑出去泄露多少

算完，中子相关全部结果装进盒子。

### 步骤 5：加工输出结果（后处理）

对应 EDI: 工具（第 3.9 节）。原始计算数据不能直接看、不能直接给别的软件用。（真麻烦，这软件可读性太差了，真得控制你了 DRAGON）

做三件事：

1. 统计：每个位置产生多少热量，各个反应发生多少次；
2. 压缩：把密密麻麻小格子，合并成大块；把很多组能量合并成少数几组；
3. 导出：存成文件，给人看，或者给别的反应堆软件接着算。

- 压缩会引入误差，用 SPH: 工具（第 3.11 节）计算 SPH 修正系数，用来抵消均匀化、能群压缩带来的通量不连续误差。

### 附加可选工序：模拟燃料越烧越旧（EVO 燃耗模块）

对应原文档 EVO: 模块（第 3.10 节）。

> 非必跑工序。只有需要模拟**时间推移**、燃料持续发生变化时，才启用这个模块。

工作流程：

1. 先完成前面整套计算，得到**当前时刻中子撞击燃料的强弱数据**；
2. EVO 利用这份撞击数据，模拟反应堆又运行了一段时间：一部分燃料原子被中子打没，同时生成氙、钚等新的物质；
3. 修改「材料盒子」(microlib)，把里面各类原子的数量更新成烧过之后的新配比；
4. 用更新后的燃料配比，**重新计算中子**：
   - 绝大多数情况：只是燃料成分变了，燃料的大小、外形没有变，之前扫描得到的几何数据可以直接复用，不用重新扫描模型；
   - 特殊情况：燃料高温膨胀变形，外形发生改变，就需要重新扫描几何，再去算中子。

不断重复上面 1-4 的整套过程，一轮代表反应堆又运行了一段时间。
多轮循环跑完，就能拿到燃料从崭新，到烧 1 天、100 天、1000 天逐步老化的全套结果。

> 提醒：EVO 本身**不会计算中子**，它只负责修改燃料成分。改完燃料之后，一定要重新算中子，不然结果完全错误。

## 指令文件怎么写（Cle2000 怎么写）

一份指令文件就是一串命令，骨架长这样（伪代码，具体看第八章）：

```text
LINKED LIST 盒子1 盒子2 ... ;     ! 指定哪些盒子放内存（跑得快）
XSM FILE 盒子3 ... ;              ! 哪些盒子存硬盘文件（省内存）

LIB: ... :: 参数 ;                ! 逐条调用模块：
GEO: ... :: 参数 ;                !   :: 左边写要操作的盒子名，右边写参数
EXCELT: ... :: 参数 ;             !   （输出盒子写在最左边，加 := ）
ASM: ... :: 参数 ;
FLU: ... :: 参数 ;
EDI: ... :: 参数 ;

END: ;                            ! 收工，程序停
```

- Cle2000 规矩（第 2 章）：
  - 一行一条命令，分号结尾；
  - 注释三种写法：整行以 `*` 开头、行内 `;` 之后、或者 `(*` 和 `*)` 包住的部分，程序都会跳过；
  - 理论上 `END:` 不写程序也会在读完文件后自动收工，但养成写的习惯。
- 进阶（第 11 章，CLE-2000 语言）：指令文件里还能写变量、循环、条件判断。比如燃耗要循环上百轮，就是靠文件里写一个循环，让"算中子 → 烧一点 → 再算"自动转起来。脚本文件后缀是 `.x2m`。
