# GANLIB5使用指南

## GANLIB5是啥

- GANLIB5 是一个软件互操作中间层库，不是完整的应用软件，而是被其他软件链接调用的“粘合剂”。它的核心使命是：
	- 让多个独立开发的软件模块（甚至用不同语言写的）能够标准化地交换数据、组织计算流程、持久化存储，而不需要每个模块自己造一套数据格式和调度机制。

它由两个核心组件构成：

| 组件 | 角色 | 类比 |
| --- | --- | --- |
| LCM对象 | 数据传输容器 | 像 Python 的嵌套字典 + 列表 + NumPy 数组的混合体 |
| CLE-2000 | 流程监督器/调度器 | 像一个轻量级的“计算流程脚本引擎”，能读输入、调度模块、控制循环 |
	
它最初是为核反应堆物理代码（如 DRAGON、TRIVAC、DONJON）开发的，用来解决这些代码之间“数据怎么传、模块怎么串”的问题。

## 为什么需要它？——先看没有它时的痛点

假设你在做一个多物理仿真，涉及：

- 一个中子输运模块（Fortran 写的）

- 一个热工水力模块（C++ 写的）

- 一个燃耗计算模块（Python 写的）

没有 GANLIB5 时，你会遇到：

**数据格式不统一**
每个模块有自己的输入输出格式，A 模块的输出要手动转成 B 模块的输入，容易出错、难维护。

**内存管理混乱**
谁分配、谁释放、跨语言传递指针时地址宽度不一致（32 位 vs 64 位），容易段错误。

**流程硬编码**
想改计算顺序、加个循环、换组参数，就得改代码、重新编译。

**持久化困难**
想中途保存状态、重启计算、归档结果，每个模块都得自己实现一套。

**跨语言互操作成本高**
Fortran 和 C++ 之间传数组、传字符串、传结构体，处处是坑。

## GANLIB5 怎么解决这些问题
1. 统一数据容器：**LCM 对象**
LCM 对象是一棵自描述的树：

关联表：键值对，键是 12 字符名，类似字典。

异构列表：有序元素，按索引访问，类似列表。

基本类型数组：int32、float32、char4、float64、logical32、complex64。

这棵树可以：

**驻内存**（快，适合频繁小块数据）

**持久化到 XSM 文件**（省内存，适合大对象）

被 C、Fortran、Python 透明读写

好处：模块之间不再需要自定义数据格式，大家都往 LCM 树里读写，接口标准化。

2. 流程与代码分离：CLE-2000
CLE-2000 让你用自由格式的脚本描述计算方案：

调用哪些模块

按什么顺序

传什么参数

加什么循环和条件

好处：改计算方案不用改模块代码、不用重新编译。模块只负责“算”，CLE-2000 负责“怎么串”。

3. 跨语言互操作：多套 API 绑定
GANLIB5 提供：

ANSI C API：原生接口，最底层。

ISO Fortran 2003 API：用 TYPE(C_PTR) 包装 C 指针，64 位兼容。

Python3 API（PyGan）：把 LCM 映射成 Python 字典/列表/NumPy 数组，把 CLE-2000 封装成类。

好处：不同语言写的模块可以无缝协作，不需要为每种语言组合写适配层。
