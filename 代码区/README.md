## Cle2000 唯一核心语法

**输出对象 := 模块名：输入对象：：模块数据；**（记得最后要加；）

e.g.

```
FLUX := FLU: SYS MACRO TRACK :: TYPE K ;
```

意思是：用 **FLU:** 模块，给模块喂 **SYS MACRO TRACK** 这三个盒子，数据段写 **TYPE K** （代称，可以写很长），计算完后吐出一个叫 **FLUX** 的盒子，这个盒子的名字可以随便取，你给他取名为*SHIT*都行。

**人话版： 整个指令文件干的就是，调用一个个模块，给这些模块喂数据盒子，然后这些模块会吐出来新的数据盒子，搞个变量把他接住**

模块必须先在文件开头声明有哪些 MODULE

e.g.

```
MODULE GEO: SYBILT: MAC: ASM: FLU: EDI: DELETE: END: ;
```

数据对象也必须先声明：

e.g.

```
LINKED_LIST MACRO ANGEO TRACK SYS FLUX EDITION ;
```

## CLE‑2000 书写规则

1. 文件后缀：主文件 `.x2m`，过程文件 `.c2m`
2. 每行不能超过 132 字符，只有前 120 字符有效
3. `*` 或 `!` 后面是注释
4. `(* ... *)` 之间是注释
5. 区分大小写
6. 空格是分隔符
7. 禁止 Tab
8. 对象名最多 12 字符
9. 每条模块调用最后要有 `;`
10. 嵌入模块用 `:::`
11. 每个模块名称是自带`:`的，比如 `FLU:` , `MAC:`

## 关于 .x2m 文件

- 这个是个**纯文本输入文件**，用文本编辑器打开就行，或者和我一样用 *Notepad++*。
- 文件一般放在 DRAGON 的 Dragon 目录下。

![就是这里](../material/Dragon%E6%96%87%E4%BB%B6%E7%9B%AE%E5%BD%95.PNG)

- 创建：打开 Ubuntu 终端，进入 Dragon 目录，用 nano 新建文件

```
nano 名字.x2m
```

- 保存：`Ctrl + O` ；退出：`Ctrl + X`。

> 
> 这些是 Ubuntu 指令，详细请出门左转查看 Linux 指令怎么写。

- 运行要在 **Ubuntu 终端** 里用 DRAGON 的 **rdragon 命令**

```
./rdragon 名字.x2m
```

- 如果提示权限不够：

```
chmod +x rdragon
```

- 运行后会在当前目录生成输出文件，比如 *tcm01_min.lst*、*tcm01_min.out* 或者 `.xsm` 文件，取决于你的输入。

## 各个 MODULE 的解释

这个很重要，只有搞懂每个模块才知道指令到底怎么写，这也是最核心的地方，学会这个就直到指令文件怎么写了

先说一下每个模块要吃什么盒子，会吐出来什么盒子，这个关系到每个模块调用的**第一行**怎么写

对应到*实例 tcm01_min.x2m*就是这些行

```
MACRO := MAC: ::
......
ANGEO := GEO: ::
......
TRACK := SYBILT: ANGEO ::
......
```

表格

| 模块 | 吃几个输入盒子 | 吐出几个输出盒子 |
| --- | --- | --- |
| MAC: | 0 | 1 个（宏观截面库） |
| GEO: | 0 | 1 个（几何） |
| SYBILT: | 1 个（几何） | 1 个（跟踪） |
| ASM: | 2 个（截面 + 跟踪） | 1 个（碰撞概率矩阵） |
| FLU: | 3 个（矩阵 + 截面 + 跟踪） | 1 个（通量） |
| EDI: | 3 个（截面 + 跟踪 + 通量） | 1 个（编辑结果） |

下面解释一下这些模块为什么要吃这些盒子

- 要想理解哪些模块吃哪些盒子，其实看他们吐出什么盒子就知道了

比如，SYBLIT: 吐出的是跟踪盒子，跟踪需要什么？几何

> 
> 甭管具体理由，你就说有没有道理，你玩捉人游戏，把你眼蒙住你还能抓吗，肯定要给你个地图，或者你心里对地形有数才能行动啊

比如，ASM: 吐出碰撞概率盒子，需要的就是截面和跟踪盒子

> 
> 可以理解为，鬼捉人游戏种，想知道鬼有没有撞到墙，首先要知道这个墙的材质是什么（截面盒子），然后要知道鬼的行动轨迹是什么（跟踪盒子），才能知道有没有撞到墙

- 以此类推，自己天马行空地想一想就行了
- 其中特别注意的是， MAC: 和 GEO: 都属于无中生有，你要自己去定义，所以不用吃任何盒子。

## 每个 MODULE 怎么用

### MAC:

首先解释这个模块干嘛的

- **计算截面**

很重要的事：截面并不是我们理解的截面的意思，在这里可以说是一个特殊名字，这个词表示的是：
**这块材料对中子的反应能力**

解释如下：

想象一颗中子飞进一块材料。它只有三种结局：

- 撞上原子，被吸收（原子吃掉它）
- 撞上原子，被散射（改变方向，改变能量，继续飞）
- 什么都不撞，直接穿过去

材料对中子的 "反应能力"，用**截面**衡量。

- 截面 = 中子撞上原子的概率（第一种结局的概率）
- **一个材料有哪些参数，怎么用**

可对照 *实例 tcm01_min.x2m* 进行学习

MAC: 一个材料的参数 90% 的情况只用到四个（其实文档中一共有十几个）：
`TOTAL、SCAT、NUSIGF、CHI`

- **TOTAL**
- 意思：中子飞进这块材料，撞上任何原子的总概率。吸收 + 散射 全算上。
- 写法：每个能群一个数，有多少个群写多少个数：             *（什么是能群呢？接着往下看）*

```
TOTAL 0.222222 0.833333
```

NGRO 是 2，第一个数 0.2222…… 就是群 1，第二个数 0.8333…… 就是群 2

> 
> NGRO 是 Number of GROup 简写。 对，取字母的位置就是这么奇怪
> 同理缩写，NMIX 是 Number of MIXture，NIFI 不用管，一般都是 1

- 能群的顺序很重要，群 1 是最高能量（快群），群 2 是最低能量（热群） （不一定是群 2，如果你有 8 个群，那群 8 就是热群）

> 
> 能群是什么：
> 当一颗中子从核裂变中 b 蹦出来的那一刻，能量很高（约 200 万电子伏特，2 MeV）。它在材料里飞，一路撞原子，一路损失能量，最后慢下来，变成 "热中子"（能量约 0.025 电子伏特）。
> 能量跨度：从 200 万 eV 到 0.025 eV，差了 8 亿倍。

问题来了：**能量是连续的**

理论上，中子的能量可以是 0.025 eV 到 2 MeV 之间的任何值。有无限多个可能。

如果 DRAGON 对每一个能量值都单独算一遍截面、算一遍碰撞概率、算一遍通量…… 那它**永远算不完。**

解决办法：把能量切成段

把 0.025 eV 到 2 MeV 这整条能量轴，切成若干段。

每一段叫一个能群（energy group）。

```
能量高
  2 MeV  ┬────────────── 群 1
         │
         ├────────────── 群 2
         │
         ├────────────── 群 3
         │
         ├────────────── 群 4
         │
  0.025eV┴────────────── 群 NGRO
能量低
```

每一个能群里，我们认为中子的能量是 "一样的"（取这段能量的某种平均值）。

这样，无限多的能量值，就变成了有限个能群。DRAGON 只需要对每个能群算一套数据，不用对无限多个能量值算。

所以：**"能群" = 把连续的能量轴切成有限段，每段叫一个能群。**

**也可以理解成，能群就是定义中子有哪些 “速度”**

能群的数量：算得准不准和算得快不快之间的取舍

能群少，就快，但不准

能群多，慢，但准

实例中 NGRO 是 2 ， 实际中一般计算用 69 群或更多

**能群里的数据是怎么来的**

既然是 "一段能量里的平均值"，那怎么平均？

用**通量加权平均**

意思：这段能量里，中子多的能量点，权重更大；中子少的能量点，权重更小。

举例：群 1 里，1.5 MeV 处中子特别多，0.8 MeV 处中子少。那么群 1 的 "平均截面" 更接近 1.5 MeV 处的截面值。

这就是为什么必须先知道通量，才能算群平均截面 —— 但通量本身又需要截面才能算。这是一个鸡生蛋蛋生鸡的问题。 实际计算里用迭代解决，但初学不用管。现在只要知道 "群数据是通量加权的平均值" 就行了。

**为什么要有能群的概念**

因为，同一个材料对不同的能量（速度）的中子反应会不同，截面也就不同

- **SCAT**
- 意思：中子从能量群 A 撞到能量群 B，这个过程的概率是多少。
- 格式：按源群分组，每组写一行：源群 目标群起始 值₁ 值₂ … 值ₜ
规则：
- 目标群起始 = t，后面必须跟恰好 t 个值
- 值的顺序：第 1 个 = 源群 → t，第 2 个 = 源群 → (t-1)，最后一个 = 源群 → 1。
- 所有组可以写在同一行，也可以分行写。分行只是排版，不影响解析。
```
SCAT
1 2 0.03 0.25	*(1->2 , 1->1)
2 2 0.65 0.01	*(2->2 , 2->1)
```
实例：
```
SCAT
1 1
0.19222
2 2 0.75333 0.02
```

补充

- 首先要知道，中子散射时，一般会损失能量（撞上原子核，一部分动能变成原子核的反冲能）。
- 所以正常散射 = 从高能群 → 低能群
- 有例外，比如上面这个例子，有群 2 到群 1 的，这个叫上散射，你会发现概率要比其他低得多
- 没有定义的散射方向，就默认概率是 0
- **NUSIGF**
- 意思：中子撞上燃料原子引发裂变，裂变一次放出多少个新中子。 （这里有个公式的，νΣf，中子产额 × 裂变截面 ，不用懂，因为我也不懂）
- 写法： 每个能群一个数。

```
NUSIGF
0.0 0.135
```

意思是：群 1 不裂变（0），群 2 的 νΣf = 0.135。

**为什么快群通常不裂变？**

因为热中子（就是低能那一堆中子）引发裂变的概率是快中子的**几百倍**。

- 但并不是所有堆都是这样的，NUSIGF 在哪个群大，取决于堆型和材料。不是所有堆都 "快群不裂变"。
- 比如 CANDU，这个重水堆就是热群裂变占主导
- **CHI**
- 意思：裂变产生的新中子，出生在哪个能群。
- 写法： 每个能群一个数。所有数加起来必须 = 1.0

```
CHI 1.0 0.0
```

意思是：所有新生中子 100% 出生在群 1（快群），群 2 没有新中子出生

- **其他不太重要的格式规范**

> 
> 其实参考 *实例 tcm01_min.x2m* 就知道了

1. 从`READ INPUT`开始定义材料，然后写 `MIX1` 然后就是上面那些参数
2. 在`READ INPUT`之前要写`NGRO,NMIX,NIFI`给个总定义
3. 用一个 `;` 来结束 MAC: 指令的编写

### GEO:

- 这个模块就是定义、画几何模型

下面把实例的代码粘贴过来，逐行看

```
ANGEO := GEO: ::
TUBE 2
R+ REFL
RADIUS 0.0 0.19653 1.0
MIX
1
2
SPLITR
1
4
;
```

- 第一行不说了，和 MAC: 那个一样
- `TUBE 2` ，定义画什么形状，这里定义了 “圆筒”
  - *TUBE* 在 DRAGON 里指：同心圆环。就是往一个圆心外面套一圈一圈的圆环。
  - 2 是 圆环的数量。所以这里有 2 个圆环。
- 所以这个几何模型大概长这样

```
            外边界
        ┌───────────┐
        │  ╭─────╮  │
        │  │  ●  │  │      ● = 圆心
        │  ╰─────╯  │
        └───────────┘
        ↑           ↑
      内环         外环
```

- `R+ REFL` ，边界条件。 中子飞到几何最外面的时候，怎么办？
  - R+ = 径向外侧边界（就是最外圈那个圆）。
  - REFL（全称是 Reflective） = 反射。中子撞到边界，原样弹回来。相当于 "外面还有一模一样的燃料块"。
- **为什么要这样设？**
  - 因为 DRAGON 只算一个栅元，但栅元外面还有别的栅元。设反射边界 = "假装外面也有同样的东西"，这是栅元计算的标配。
- `RADIUS 0.0 0.19653 1.0` ，半径
  - 0.0 = 圆心
  - 0.19653 = 第一个圆环的外半径（cm）
  - 1.0 = 第二个圆环的外半径，也就是整个几何的外边界（cm）

> 
> 注意：有 2 个圆环，就有 3 个半径值（因为要 2 个 "圈" 就需要 3 条边界线：最内、中间、最外）。

- `MIX` 后面跟两个数，材料编号，顺序是从内到外。
  - 第 1 个圆环（0.0 ～ 0.19653）填材料 1
  - 第 2 个圆环（0.19653 ～ 1.0）填材料 2

> 
> 括号里的数就是上一条 RADIUS 弄得半径值

- **这两个编号必须对应 MAC: 里定义过的 MIX 1 和 MIX 2。 不对应就报错。**
- `SPLITR` 后面跟两个数，虚拟细分。告诉跟踪模块（SYBILT:）"积分的时候，每个圆环内部再切几刀，提高精度"
  - 第 1 个圆环切 1 刀（等于不切）
  - 第 2 个圆环切 4 刀
- 这不改变真实物理区域的数量。 只是让积分更细。以后慢慢体会。
- 可以不写，默认不细分
- 最后依旧用 `;` 结束

**PLUS**

- 边界条件必须写，有以下三种

表格

| 写法 | 意思 | 什么时候用 |
| --- | --- | --- |
| R+ REFL | 反射，中子原样弹回 | 栅元计算（标配） |
| R+ VOID | 真空，中子飞出去就没了 | 想做泄漏计算 |
| R+ ALBE 值 | 部分反射 | 高级用法，先不管 |

### SYBILT:

**这是啥**

- 扫描几何模型的
- 刚刚我们已经使用了两个模块 MAC: GEO: ，我们已经有了两个盒子： MACRO 和 ANGEO
- 而在这个模块下面的一个模块 ASM: 要算一个核心量，**中子从区域 i 出发，撞到区域 j 的概率。**
- ASM: 算的概率要怎么来？取决于两件事：
  - 从 i 到 j 有多远 —— 中子要飞过多少路程才可能撞上 j
  - 沿途的材料有多 "厚"—— 中子一路飞过去，会被 i 和中间的材料吸收掉多少
- 所以 ASM: 需要知道：每一条可能的飞行路线，穿过每个区域的长度是多少。
- 而这个量就是 SYBILT: 来算的

**人话版：虚拟发射一大堆射线，扫过整个几何，记录每一条射线穿过每个区域的长度。**

> 
> 所以这个模块需要喂给他几何盒子

调用句式：

```
TRACK := SYBILT: ANGEO :: 参数 ;
```

实例代码：

```
TRACK := SYBILT: ANGEO ::
TITLE 'TCM01 minimal'
EDIT 1 MAXR 5 QUA1 5 ;
```

逐行解释：

- `TITLE '...'`
- 给你的扫描起个标题。 写什么无所谓，一个名字而已
- `EDIT 1`
- 输出详细程度。
  - EDIT 0 = 不打印
  - EDIT 1 = 只打基本信息（体积、表面积）
  - EDIT 2 = 更详细（打印区域编号、每条射线信息）
- 初学建议用 EDIT 1。
- `MAXR 5`**重点**
- MAXR = 你要预留多大的空间给 "区域"。
- **但是**，这个数字不是 "几何里真实区域数"，而是 "细分之后的总区域数"。
- 回头看 GEO: 写的`TUBE 2` 这是真实区域`SPLITR 1 4` 这是细分了的区域
- 所以总区域数是 1 + 4 = 5
- 所以 MAXR 5 是固定的（数字小了会报错）（但是大了不会）
- `QUA1 5`**重点**
- *角度求积*
- 什么意思：跟踪要发很多方向不同的射线。QUA1 就是 "发多少种角度"。
  - QUA1 5 = 用 5 个不同的角度去扫
  - QUA1 10 = 10 个角度

-**角度越多，覆盖越全面，碰撞概率算得越准，但也越慢。**

> 
> 鱼和熊掌不可兼得嘛，和 精度宽度 不可同时有一个道理

- 因为 1D 圆柱几何是径向对称的，中子沿各方向飞的概率不同，但所有方向加权的总和要对。QUA1 5 是常用的基础值，够用。
- 建议：初学者用 5～8 就够。

> 
> 解释一个这个模块吐出的盒子： TRACKING 装了啥

表格

| 装的量 | 什么时候用 |
| --- | --- |
| 体积：每个区域有多大 | FLU: 后面要用它做通量归一化。 |
| 表面积：每个区域的外表面多大 | 碰撞概率矩阵的对角项要用它。 |
| 弦长：一条射线穿过某个区域，走了多远 | ASM: 算碰撞概率的核心。 |
| 角度权重：每个方向的重要程度 | 求和的时候要用。 |

> 
> 所以后面会看到 TRACK 被多个模块重复使用，都是在从这四样东西里各取所需。

**PLUS**

*边界条件对跟踪的影响*

- 如果几何是 R+ REFL，SYBILT: 扫描的时候知道 "中子到边界会弹回来"，所以它只扫半个周期就够了。
- 如果几何是 R+ VOID，SYBILT: 要扫描中子从内部飞出去的所有路径，因为飞出去就没了，不会反射回来。
- 所以同样一个几何，边界条件改了，跟踪也得重新做。 后面 EVO: 燃耗计算里，如果只是材料变了、形状没变，跟踪可以复用 —— 因为边界条件没变。

### ASM:

假设栅元被分成了无数个小房间（ GEO: 中 SPLITR 切出来的空间）

现在有一个中子出生在 i 空间，他有三种结局：

1. 在 i 房间撞了 （还没飞出去就被吸收或散射）
2. 飞到 j 房间，撞了
3. 如果边界设置成了 VOID，会有一种情况是，一路都没撞，飞走

**碰撞概率 P (i→j) 就是：从房间 i 出生的中子，最终在房间 j 里被撞的概率。**

- **矩阵**

有 N 个房间，就有 N × N 个 P (i→j)

把它们排成一个表格：

```
        撞在 j=1  撞在 j=2  撞在 j=3
从 i=1  P(1→1)    P(1→2)    P(1→3)
从 i=2  P(2→1)    P(2→2)    P(2→3)
从 i=3  P(3→1)    P(3→2)    P(3→3)
```

- 行 = 从哪出发
- 列 = 在哪被撞

这个表格就叫**碰撞概率矩阵**,**ASM: 算出来的就是这个东西。**

（如果有 VOID 边界，还要多一列：P (i→逃出去)。不过初学先不管。）

- **为什么 ASM: 需要 MACRO 和 TRACK**

因为 P (i→j)  取决于两件事：

1. 中子飞的过程中，会被沿途的材料吃掉多少？ - 这个由材料，即 MACRO 决定
2. 中子从 i 飞到 j，要飞多远？ - 这个由 TRACK 决定 （弦长 + 体积）

- 注意：**每个能群都有一张独立的碰撞概率矩阵**

> 
> 如果算 69 群，ASM: 就算出 69 张 N×N 的矩阵。

- **调用句式**

```
SYS := ASM: MACRO TRACK :: 参数 ;
```

> 
> MACRO 和 TRACK 这两个盒子的顺序没讲究，谁前谁后没关系

- **参数**

ASM: 的常见参数很少，一般就一个：
`PIJ`

可以一行写：

```
SYS := ASM: MACRO TRACK :: PIJ ;
```

PIJ = 告诉 ASM：算完整的碰撞概率矩阵。

> 
> 还有别的参数（SKIP、NORM、ALBS、ECCO），初学全都先不管。它们都是高级优化选项

### FLU:

- **这是啥**

前面所有步骤（MAC、GEO、SYBILT、ASM）都是在准备原料。

FLU: 是真正开火的那一步。它把原料扔进方程，算出 DRAGON 最终要交给你的两个核心结果：

**通量**：每个区域、每个能群，中子有多密集
**keff**：这套系统能不能自我维持链式反应

**输出盒子**

FLU: 吐出来的盒子，官方类型叫 FLUXUNK。里面主要装：

1. 通量数组 ： N 个区域 × NGRO 个能群，每个格子一个通量值
2. keff ： 一个数
3. 裂变源分布 ： 每个区域每群产生多少裂变中子
4. 收敛信息 ： 迭代了几次、误差多大

- **为什么吃 3 个盒子**

```
FLUX := FLU: SYS MACRO TRACK :: TYPE K ;
```

FLU: 要吃 碰撞概率盒子、截面盒子、跟踪盒子

1. SYS ： 回答 "中子从 i 出生，会撞到哪"

> 
> 区域 1 里的中子，有 40% 在区域 1 被撞，30% 在区域 2 被撞，……  没有它，FLU 根本不知道中子在空间里怎么分布。

2. MACRO ： 回答 "撞上之后，是吸收还是散射"

> 
> SYS 只告诉你 "撞在哪"。撞上之后发生什么，它不知道。 截面盒子告诉你装上后，被吸收？被散射到其他能群（换个能量继续飞）？裂变（产生新中子）？

3. TRACK ： 回答 "每个区域多大"

> 
> SYS 里存的是 "概率"。但通量是 "密度"（每单位体积里有多少中子）。
> 概率 → 密度，中间差一个体积。
> TRACK 盒子里有每个区域的体积。FLU 用它把 "概率" 换算成 "物理量"。

**总结**：SYS 给形状，MACRO 给规则，TRACK 给尺寸。三个一起，才能算出真实的通量。

- **通量到底长什么样**

FLU 算完之后，会得到的一张表：

```
             群 1（快）    群 2（热）
区域 1（燃料）   Φ₁₁          Φ₁₂
区域 2（水）     Φ₂₁          Φ₂₂
```

每个格子里是一个数。这个数的意思是：
*在这个区域、这个能群里，每平方厘米、每秒，飞过去多少个中子。*

e.g.
Φ₁₁ = 100 → 区域 1 的快群通量是 100 中子 /(cm²・s)
Φ₁₂ = 500 → 区域 1 的热群通量是 500 中子 /(cm²・s)

数字越大，说明这个区域这个能群里中子越多、越活跃。

** 为什么燃料区的热群通量通常很大？ **

因为热中子容易在燃料里引发裂变（上面讲过），裂变又产生更多中子，形成循环。这是一个自洽的过程。

- **keff**

keff = 有效增殖系数。

人话：这一代中子，能生出几倍于自己的下一代中子？

表格

| keff 值 | 含义 |
| --- | --- |
| keff = 1.000 | 正好维持。一代生一代，不多不少。临界 |
| keff > 1 | 下一代比这代多。链式反应增长。超临界 |
| keff < 1 | 下一代比这代少。链式反应衰减。次临界 |

反应堆正常运行，keff 必须精确等于 1（实际运行略高于 1，多余部分被控制棒吸收掉）。

DRAGON 算 keff 的目的：给你一个 "这套栅元设计能不能让反应堆自我维持" 的答案。

- **参数 TYPE K**

```
FLUX := FLU: SYS MACRO TRACK :: TYPE K ;
```

TYPE K = 告诉 FLU：我要算 keff。

FLU 支持好几种求解类型，初学只看两个：

表格

| 写法 | 算什么 | 什么时候用 |
| --- | --- | --- |
| TYPE K | keff 本征值 | 裂变材料，求临界 |
| TYPE S | 固定源问题 | 没有裂变，或加外部源 |

### EDI:

- **这是啥**

最后一部分了，**加工和导出**

- **为什么需要 EDI:,FLU: 算完的不能直接用吗？**

FLUX 盒子里装着：每个区域、每个能群的通量，但问题是：

1. 太细了，数据量爆缸大。交给 DONJON 算全堆，DONJON 会卡死。因为全堆有上千个栅元，每个栅元 6900 个通量值……
2. 截面也是按细群存的。 MACRO 里也是每个区域、每个能群的截面。如果算 69 群，DONJON 也用 69 群，计算量同样爆炸。能群也必须压缩。
3. 每个区域都是独立材料。燃料区是燃料，包壳是包壳，水是水。DONJON 算全堆，只需要知道 "这个栅元整体的等效截面"，不需要知道 "栅元内部每个小区域分别是什么"。区域必须合并。

> 
> 以上理由不用完全搞懂，大概知道就行了，反正就是得加工，不然算不了

- **EDI: 要做的三件事**

表格

| 动作 | 大白话 | 参数关键词 |
| --- | --- | --- |
| 合并区域 | 把栅元里的小区域，合并成一个大区域 | MERG |
| 合并能群 | 把 69 群压缩成 2 群或 4 群 | COND |
| 导出 | 把加工后的结果存起来 | SAVE |

- **调用句式**

```
EDT := EDI: MACRO TRACK FLUX :: 参数 ;
```

- 吃 3 个输入：MACRO（细群截面）+ TRACK（几何）+ FLUX（细群通量）
- 吐 1 个输出：EDT（EDITION 盒子，加工后的结果）

为什么又是这三个？ 因为压缩需要知道：

1. MACRO：原始细群截面
2. FLUX：原始细群通量（压缩时用通量做加权平均）
3. TRACK：每个区域的体积（合并时按体积加权）

压缩的本质是 "加权平均"。 权重就是通量和体积。所以三个盒子一个都不能少。

**三个参数**

- `MERG`：合并区域

作用：把多个小区域合并成一个大区域。

写法有两种：

方式 A：按材料编号合并

```
MERG MIX
1 2 3
```

意思是：区域 1、2、3 合并成一个新区域。

方式 B：按区域编号合并

```
MERG REGI
1 1 1 2 2 2 3 3
```

意思是：旧区域 1、2、3 → 新区域 1；旧区域 4、5、6 → 新区域 2；旧区域 7、8 → 新区域 3。

初学建议：只学 `MERG MIX`，简单。

- `COND`：合并能群

作用：把细群压缩成粗群。

写法：

```
COND 2
```

意思是：把 69 群压缩成 2 群。

DRAGON 默认会分成 "快群 + 热群"。具体怎么分，可以由你指定分界能量，也可以让它自动分。

初学 `COND 2` 就够用。

- `SAVE`：保存

作用：把加工结果存进 EDITION 盒子。

> 
> SAVE 后面可以跟 ON ' 名字 ' 来给这次保存起个名，方便后面引用。初学不写也行。

一个完整的例子:

```
EDT := EDI: MACRO TRACK FLUX ::
    EDIT 3
    MERG MIX 1 2 3
    COND 2
    SAVE
    ;
```

**输出 EDT 盒子里装的是： 1 个合并后的区域 + 2 个压缩后的能群 + 一套等效截面和通量。**

这就可以交给 DONJON 了。

- **重要提醒：压缩一定会引入误差。**

因为原来 69 群算得准，压成 2 群之后，粗群的等效截面是 "通量加权平均"。这种平均会丢掉一些细节，导致算出来的 keff 和细群算的 keff 不完全一样。

解决办法：**SPH 修正。**

SPH: 模块（第 3.11 节）会算出一套 "修正系数"，乘在压缩后的截面上，让粗群计算的反应率和细群计算的完全一致。

- `EDIT 3`是啥

**EDI: 的 EDIT 等级**

EDIT 参数控制打印多少东西：

表格

| 值 | 打印什么 |
| --- | --- |
| EDIT 0 | 不打印 |
| EDIT 1 | 通量和反应率 |
| EDIT 2 | 加上细群 / 粗群截面 |
| EDIT 3 | 加上散射矩阵 |
| EDIT 4 | 加上所有细节 |

---

到这里，最基本的指令文件就讲完了

一个最小可用算例的所有模块都认识了：

```
MODULE MAC: GEO: SYBILT: ASM: FLU: EDI: END: ;
LINKED_LIST MACRO ANGEO TRACK SYS FLUX EDT ;
MACRO := MAC: :: ... ;              ← 造材料
ANGEO := GEO: :: ... ;              ← 造几何
TRACK := SYBILT: ANGEO :: ... ;     ← 造跟踪
SYS   := ASM: MACRO TRACK :: PIJ ;  ← 造矩阵
FLUX  := FLU: SYS MACRO TRACK :: TYPE K ;  ← 算通量
EDT   := EDI: MACRO TRACK FLUX :: ... ;    ← 加工导出
END: ;
```

这 6 行就是 DRAGON 的 "最小骨架"。 任何简单算例，都是这 6 行的变体。

以上讲义实例在这 ： [实例 tcm01_min.x2m](./%E5%AE%9E%E4%BE%8B/tcm01_min.x2m)

## 关于宏观与微观 & MAC 与 LIB

这里需要先澄清一个最基本的概念：

一个中子在材料里飞行，撞击的对象是什么？

- 是 **原子核**

一块燃料里包含多种原子核，例如：

- U235 原子核
- U238 原子核
- O16 原子核

中子在材料中穿过时，可能撞上其中任意一种原子核。

每一种原子核对中子都有自己的反应概率，这个概率叫做：

> 
> **微观截面（microscopic cross section）**
> 
> 
> 符号：\(\sigma\)（小写 sigma）
> 
> 
> 单位：barn

因此可以理解为：

- **微观截面** = 单个原子核的反应概率

---

## 宏观截面

中子在材料中飞行时，并不会一直追踪自己具体撞上了哪一个原子核，它感受到的是 “这块材料整体” 的反应能力。

这块材料中，所有原子核的贡献叠加起来，就是材料的总反应概率。

宏观截面的计算方式是：

> 
> 每种原子核的微观截面 × 该原子核的数密度，再把所有原子核的贡献相加。

公式：

\(\Sigma = N \times \sigma\)单位：\(\mathrm{cm^{-1}}\)

如果材料中有三种原子核，则：

```
Σ = N₁σ₁ + N₂σ₂ + N₃σ₃
```

### 一句话总结

表格

| 概念 | 含义 |
| --- | --- |
| 微观截面 \(\sigma\) | 单个原子核的反应概率 |
| 宏观截面 \(\Sigma\) | 一整块材料的总反应概率 |

---

## 回看实例中的 MAC:

实例中 `MAC:` 的写法大致是：

```
MACRO := MAC: ::
NGRO 2 NMIX 2 NIFI 1
READ INPUT
MIX 1
TOTAL 0.222222 0.833333
SCAT ...
;
```

这里手写的：

```
TOTAL 0.222222 0.833333
```

直接给出的就是**宏观截面 \(\Sigma\)**。

使用 `MAC:` 时，你不需要说明材料里包含哪些原子核，也不需要说明每种原子核的数量，而是直接告诉 DRAGON：

> 
> 这块材料的总截面就是这些数值。

因此：

- `MAC:` 生成的库叫做 **MACROLIB**
- MACROLIB 中**只有宏观截面**
- MACROLIB **没有微观截面信息**

---

## LIB: 的例子

下面是一个 `LIB:` 的示例，当前实例中没有用到：

```
LIBRARY := LIB: ::
NMIX 3 CTRA WIMS
MIXS LIB: WIMSD4 FIL: iaea
MIX 1 600.0
O16  = '6016' 4.61309E-2
U235 = '2235' 1.66078E-4 1
U238 = '8238' 2.28994E-2 1
;
```

这段代码的意思是：

告诉 `LIB:`，材料中包含 O16、U235、U238，并给出它们各自的数密度。

然后 `LIB:` 会自动完成以下工作：

1. 从外部数据库文件（例如 `iaea`）中读取各个同位素的微观截面 \(\sigma\)
2. 利用公式：
\(\Sigma = N_1\sigma_1 + N_2\sigma_2 + N_3\sigma_3\)
  
计算宏观截面 \(\Sigma\)
3. 将微观截面和宏观截面都存入库中

因此：

- `LIB:` 生成的库叫做 **MICROLIB**
- MICROLIB 中**既有微观截面 \(\sigma\)**
- MICROLIB 中**也有宏观截面 \(\Sigma\)**

> 
> **关键：LIB 会自动生成一个内嵌的 MACROLIB，所以通常不需要再额外调用 MAC。**

PLUS：
Q: 什么MACROLIB既存 宏观截面也存微观截面？
A: 
- 微观数据（每种原子核的 σ）：给 SHI:（自屏蔽）和 EVO:（燃耗）用。它们要追到单个原子核层面。
- 宏观数据（整块材料的 Σ）：给 ASM: 和 FLU: 用。它们只需要“这块材料整体怎么反应”，不需要知道里面有什么原子。


---

### MAC 与 LIB 连用的特殊情况

MAC 与 LIB 连用，一般不是为了 “多此一举”，而是为了实现手动覆盖。

例如：

LIB 已经生成了宏观库，但你对其中某个材料的宏观截面不满意，想手动修改一部分数值，这时可以用 `MAC:` 去覆盖 LIB 生成的宏观库中的相应部分。

---

## 两条计算路线对比

### MAC 路线：手写宏观截面

```
MAC: → GEO: → 跟踪 → ASM: → FLU: → EDI:
```

特点：

表格

| 项目 | 说明 |
| --- | --- |
| 外部数据库 | 不需要 |
| 输入方式 | 直接手写宏观截面 |
| 计算速度 | 简单、较快 |
| 自屏蔽 | 不支持 |
| 燃耗 | 不支持 |
| 适用场景 | 教学、测试、算法验证 |

---

### LIB 路线：从数据库读取微观截面

```
LIB: → GEO: → 跟踪 → SHI: → ASM: → FLU: → EDI: → (可选 EVO:)
```

特点：

表格

| 项目 | 说明 |
| --- | --- |
| 外部数据库 | 需要，例如 `iaea`、`WIMSD4` |
| 输入方式 | 定义同位素及其数密度 |
| 计算速度 | 数据量大，较慢 |
| 自屏蔽 | 支持 |
| 燃耗 | 支持 |
| 适用场景 | 真实工程计算 |

---

## 两条路线的差别在哪里？

两条路线的差别主要在前端：

- **造材料的模块不同**
- **LIB 路线中间多了一个 `SHI:`**

但后面的模块基本一致：

```
ASM: → FLU: → EDI:
```

也就是说，一旦材料库生成完成，后续的碰撞概率计算、通量计算和结果加工逻辑是相同的。

---

## 为什么自屏蔽必须用 LIB，不能用 MAC？

自屏蔽修正的是这样一种效应：

> 
> 在燃料块内部，某些共振能区的中子被表层燃料大量吸收，导致燃料内部该能区的中子数量减少。

这种效应不是材料简单地 “整体变少”，而是和具体同位素的共振吸收有关。

因此，要做自屏蔽修正，必须知道：

- U238 的微观截面
- Pu240 的微观截面
- 或其他共振同位素的微观截面

也就是说，必须有**单同位素的微观信息**。

而：

- `MAC:` 生成的 MACROLIB **只有宏观截面**
- MACROLIB **没有各同位素的微观截面信息**
- 所以 `MAC:` **不能做自屏蔽修正**

反过来：

- `LIB:` 生成的 MICROLIB **保留了各同位素的微观截面**
- 所以 `LIB:` **可以配合 `SHI:` 做自屏蔽修正**

---

## 为什么燃耗也必须用 LIB？

燃耗计算的目的，是追踪反应堆运行过程中各同位素浓度随时间的变化。

要追踪同位素浓度变化，必须知道：

- 有哪些同位素
- 每种同位素的微观截面
- 每种同位素的反应率
- 它们如何随时间变化

因此，燃耗计算本质上依赖于**同位素层次的微观信息**。

而 `MAC:` 只提供宏观截面，不保留单同位素信息，所以：

- `MAC:` **不能做燃耗计算**
- `LIB:` **可以支持燃耗计算**

---

**进阶 MODULE 小节**

表格

| 模块 | 输入方式 | 库类型 | 包含信息 | 支持自屏蔽 | 支持燃耗 |
| --- | --- | --- | --- | --- | --- |
| `MAC:` | 直接手写宏观截面 | MACROLIB | 只有宏观截面 \(\Sigma\) | 否 | 否 |
| `LIB:` | 定义同位素和数密度 | MICROLIB | 微观截面 \(\sigma\) + 宏观截面 \(\Sigma\) | 是 | 是 |

## 库文件
**库文件 = 微观截面库**

里面存了每种核素（U235, U238, O16, Zr91 等）在不同能量（能群）下，碰到中子会发生什么反应的数据表。
用 MAC:，是自己手写截面（手算几个数）
用 LIB:，就是从库文件里查表
