## Cle2000 唯一核心语法

**输出对象 := 模块名: 输入对象 :: 模块数据 ;**（记得最后要加 ;）

e.g.

```text
FLUX := FLU: SYS MACRO TRACK :: TYPE K ;
```

意思是：用 **FLU:** 模块，给模块喂 **SYS MACRO TRACK** 这三个盒子，数据段写 **TYPE K** （代称，可以写很长），计算完后吐出一个叫 **FLUX** 的盒子，这个盒子的名字可以随便取，你给他取名为*SHIT*都行。

**人话版： 整个指令文件干的就是，调用一个个模块，给这些模块喂数据盒子，然后这些模块会吐出来新的数据盒子，搞个变量把他接住**

模块必须先在文件开头声明有哪些MODULE
e.g.
```text
MODULE GEO: SYBILT: MAC: ASM: FLU: EDI: DELETE: END: ;
```

数据对象也必须先声明：
e.g.

```text
LINKED_LIST MACRO ANGEO TRACK SYS FLUX EDITION ;
```

## CLE-2000 书写规则

1. 文件后缀：主文件 .x2m，过程文件 .c2m
2. 每行不能超过 132 字符，只有前 120 字符有效
3. * 或 ! 后面是注释
4. (* ... *) 之间是注释
5. 区分大小写
6. 空格是分隔符
7. 禁止 Tab
8. 对象名最多 12 字符
9. 每条模块调用最后要有 ;
10. 嵌入模块用 :::
11.每个模块名称是自带*:*的，比如 FLU: , MAC:

## 关于 .x2m 文件

- 这个是个**纯文本输入文件**，用文本编辑器打开就行，或者和我一样用 *Notepad++*。
- 文件一般放在 DRAGON 的 Dragon 目录下。
[就是这里](../material/Dragon文件目录.PNG)
- 创建：打开 Ubuntu 终端，进入 Dragon 目录，用 nano 新建文件

```bash
nano 名字.x2m
```

- 保存：Ctrl + O ；退出：Ctrl + X。

> 这些是 Ubuntu 指令，详细请出门左转查看 Linux 指令怎么写。

- 运行要在 **Ubuntu 终端** 里用 DRAGON 的 **rdragon 命令**

```bash
./rdragon 名字.x2m
```

- 如果提示权限不够：

```bash
chmod +x rdragon
```

- 运行后会在当前目录生成输出文件，比如 *tcm01_min.lst*、*tcm01_min.out* 或者 .xsm 文件，取决于你的输入。

## 标准模块调用顺序

- 宏观截面路线

```text
MAC:  ->  GEO:  ->  SYBILT:/EXCELT:/NXT:  ->  ASM:  ->  FLU:  ->  EDI:
```

- 微观截面路线

```text
LIB:  ->  GEO:  ->  跟踪  ->  SHI:/TONE:/USS:/AUTO:  ->  ASM:  ->  FLU:  ->  EDI:  ->  EVO:
```

- 燃耗路线

```text
LIB: -> GEO: -> 跟踪 -> SHI: -> ASM: -> FLU: -> EDI: -> EVO: -> COMPO:
```

## 各个MODULE的解释
这个很重要，只有搞懂每个模块才知道指令到底怎么写，这也是最核心的地方，学会这个就直到指令文件怎么写了

先说一下每个模块要吃什么盒子，会吐出来什么盒子，这个关系到每个模块调用的**第一行**怎么写
对应到*实例tcm01_min.x2m*就是这些行
```
MACRO := MAC: ::
......
ANGEO := GEO: ::
......
TRACK := SYBILT: ANGEO ::
......
```

| 模块 | 吃几个输入盒子 | 吐出几个输出盒子 |
| --- | --- | --- |
| MAC: | 0 | 1个（宏观截面库） |
| GEO: | 0 | 1 个（几何） |
| SYBILT: | 1 个（几何） | 1 个（跟踪） |
| ASM: | 2 个（截面 + 跟踪） | 1 个（碰撞概率矩阵） |
| FLU: | 3 个（矩阵 + 截面 + 跟踪） | 1 个（通量） |
| EDI: | 3 个（截面 + 跟踪 + 通量） | 1 个（编辑结果） |

下面解释一下这些模块为什么要吃这些盒子

- 要想理解哪些模块吃哪些盒子，其实看他们吐出什么盒子就知道了
比如，SYBLIT: 吐出的是跟踪盒子，跟踪需要什么？几何
> 甭管具体理由，你就说有没有道理，你玩捉人游戏，把你眼蒙住你还能抓吗，肯定要给你个地图，或者你心里对地形有数才能行动啊
比如，ASM: 吐出碰撞概率盒子，需要的就是截面和跟踪盒子
> 可以理解为，鬼捉人游戏种，想知道鬼有没有撞到墙，首先要知道这个墙的材质是什么（截面盒子），然后要知道鬼的行动轨迹是什么（跟踪盒子），才能知道有没有撞到墙
- 以此类推，自己天马行空地想一想就行了
- 其中特别注意的是， MAC: 和 GEO: 都属于无中生有，你要自己去定义，所以不用吃任何盒子。

## 每个MODULE怎么用

### MAC:

首先解释这个模块干嘛的

- **计算截面**

很重要的事：截面并不是我们理解的截面的意思，在这里可以说是一个特殊名字，这个词表示的是：

**这块材料对中子的反应能力**

解释如下：

想象一颗中子飞进一块材料。它只有三种结局：

- 撞上原子，被吸收（原子吃掉它）

- 撞上原子，被散射（改变方向，改变能量，继续飞）

- 什么都不撞，直接穿过去

材料对中子的"反应能力"，用**截面**衡量。
- 截面 = 中子撞上原子的概率（第一种结局的概率）

- **一个材料有哪些参数，怎么用**
可对照 *实例tcm01_min.x2m* 进行学习

MAC: 一个材料的参数90%的情况只用到四个（其实文档中一共有十几个）：

`TOTAL、SCAT、NUSIGF、CHI`

- **TOTAL**
- 意思：中子飞进这块材料，撞上任何原子的总概率。吸收 + 散射 全算上。
- 写法：每个能群一个数，有多少个群写多少个数：
```text
TOTAL 0.222222 0.833333
```
NGRO是2，第一个数0.2222……就是群1，第二个数0.8333……就是群2
> NGRO 是 Number of GROup简写。 对，取字母的位置就是这么奇怪
> 同理缩写，NMIX是Number of MIXture，NIFI不用管，一般都是1
- 能群的顺序很重要，群1是最高能量（快群），群2是最低能量（热群） （不一定是群2，如果你有8个群，那群8就是热群）

- **SCAT**
- 意思：中子从能量群 A 撞到能量群 B，这个过程的概率是多少。
- 格式是：源群 目标群 概率
```text
SCAT
1 1 0.19222       ← 从群 1 散射，还留在群 1
2 2 0.75333       ← 从群 2 散射，还留在群 2
2 1 0.02          ← 从群 2 散射，跳到群 1（上散射）
```
注意方向： 第一个数字是"从哪个群出发"，第二个是"到哪个群去"。
补充
- 首先要知道，中子散射时，一般会损失能量（撞上原子核，一部分动能变成原子核的反冲能）。
- 所以正常散射 = 从高能群 → 低能群
- 有例外，比如上面这个例子，有群2到群1的，这个叫上散射，你会发现概率要比其他低得多
- 没有定义的散射方向，就默认概率是 0


- **NUSIGF**
- 意思：中子撞上燃料原子引发裂变，裂变一次放出多少个新中子。 （这里有个公式的，νΣf，中子产额 × 裂变截面 ，不用懂，以为我也不懂）
- 写法： 每个能群一个数。
```
NUSIGF
0.0 0.135
```
意思是：群 1 不裂变（0），群 2 的νΣf = 0.135。
**为什么快群通常不裂变？**
因为热中子（就是低能那一堆中子）引发裂变的概率是快中子的**几百倍**。
- 但并不是所有堆都是这样的，NUSIGF 在哪个群大，取决于堆型和材料。不是所有堆都"快群不裂变"。
- 比如CANDU，这个重水堆就是热群裂变占主导

- **CHI**
- 意思：裂变产生的新中子，出生在哪个能群。
- 写法： 每个能群一个数。所有数加起来必须 = 1.0
```
CHI 1.0 0.0
```
意思是：所有新生中子 100% 出生在群 1（快群），群 2 没有新中子出生

- **其他不太重要的格式规范**
> 其实参考 *实例tcm01_min.x2m* 就知道了
1. 从READ INPUT开始定义材料，然后写 MIX1 然后就是上面那些参数
2. 在READ INPUT之前要写NGRO,NMIX,NIFI给个总定义
3. 用一个 *;* 来结束 MAC: 指令的编写

### GEO:
- 这个模块就是定义、画几何模型

下面把实例的代码粘贴过来，逐行看
```
ANGEO := GEO: ::
TUBE 2
R+ REFL
RADIUS 0.0 0.19653 1.0
MIX
1
2
SPLITR
1
4
;
```
- 第一行不说了，和MAC: 那个一样
- `TUBE 2` ，定义画什么形状，这里定义了“圆筒”
	- *TUBE* 在 DRAGON 里指：同心圆环。就是往一个圆心外面套一圈一圈的圆环。
	- 2 是 圆环的数量。所以这里有 2 个圆环。
- 所以这个几何模型大概长这样
```
            外边界
        ┌───────────┐
        │  ╭─────╮  │
        │  │  ●  │  │      ● = 圆心
        │  ╰─────╯  │
        └───────────┘
        ↑           ↑
      内环         外环
```
- `R+ REFL` ，边界条件。 中子飞到几何最外面的时候，怎么办？
	- R+ = 径向外侧边界（就是最外圈那个圆）。
	- REFL（全称是Reflective） = 反射。中子撞到边界，原样弹回来。相当于"外面还有一模一样的燃料块"。
- **为什么要这样设？** 
	- 因为 DRAGON 只算一个栅元，但栅元外面还有别的栅元。设反射边界 = "假装外面也有同样的东西"，这是栅元计算的标配。
	
- `RADIUS 0.0 0.19653 1.0` ，半径
	- 0.0 = 圆心

	- 0.19653 = 第一个圆环的外半径（cm）

	- 1.0 = 第二个圆环的外半径，也就是整个几何的外边界（cm）
> 注意：有 2 个圆环，就有 3 个半径值（因为要 2 个"圈"就需要 3 条边界线：最内、中间、最外）。


- `MIX 后面跟两个数` ，材料编号，顺序是从内到外。
	- 第 1 个圆环（0.0 ～ 0.19653）填材料 1

	- 第 2 个圆环（0.19653 ～ 1.0）填材料 2
	
	> 括号里的数就是上一条RADIUS弄得半径值
	
- **这两个编号必须对应 MAC: 里定义过的 MIX 1 和 MIX 2。 不对应就报错。**

- `SPLITR 后面跟两个数` ，虚拟细分。告诉跟踪模块（SYBILT:）"积分的时候，每个圆环内部再切几刀，提高精度"
	- 第 1 个圆环切 1 刀（等于不切）

	- 第 2 个圆环切 4 刀

- 这不改变真实物理区域的数量。 只是让积分更细。以后慢慢体会。
- 可以不写，默认不细分
- 最后依旧用 ; 结束

**PLUS**
- 边界条件必须写，有以下三种
| 写法 | 意思 | 什么时候用 |
| --- | --- | --- |
| R+ REFL | 反射，中子原样弹回 | 栅元计算（标配） |
| R+ VOID | 真空，中子飞出去就没了 | 想做泄漏计算 |
| R+ ALBE 值 | 部分反射 | 高级用法，先不管 |


### SYBILT:

**这是啥**
- 扫描几何模型的
- 刚刚我们已经使用了两个模块 MAC: GEO: ，我们已经有了两个盒子： MACRO 和 ANGEO 
- 而在这个模块下面的一个模块 ASM: 要算一个核心量,**中子从区域 i 出发，撞到区域 j 的概率。**
- ASM: 算的概率要怎么来？取决于两件事：
	- 从 i 到 j 有多远——中子要飞过多少路程才可能撞上 j

	- 沿途的材料有多"厚"——中子一路飞过去，会被 i 和中间的材料吸收掉多少
- 所以 ASM: 需要知道：每一条可能的飞行路线，穿过每个区域的长度是多少。
- 而这个量就是 SYBILT: 来算的

**人话版：虚拟发射一大堆射线，扫过整个几何，记录每一条射线穿过每个区域的长度。**
> 所以这个模块需要喂给他几何盒子

调用句式：
```
TRACK := SYBILT: ANGEO :: 参数 ;
```

实例代码：
```
TRACK := SYBILT: ANGEO ::
TITLE 'TCM01 minimal'
EDIT 1 MAXR 5 QUA1 5 ;
```

逐行解释：

- `TITLE '...'`
- 给你的扫描起个标题。 写什么无所谓,一个名字而已

- `EDIT 1`
- 输出详细程度。

	- EDIT 0 = 不打印

	- EDIT 1 = 只打基本信息（体积、表面积）

	- EDIT 2 = 更详细（打印区域编号、每条射线信息） 
- 初学建议用 EDIT 1。

- `MAXR 5`    **重点**

- MAXR = 你要预留多大的空间给"区域"。
- **但是**，这个数字不是"几何里真实区域数"，而是"细分之后的总区域数"。
- 回头看GEO: 写的
`TUBE 2` 这是真实区域
`SPLITR 1 4` 这是细分了的区域
- 所以总区域数是 1 + 4 = 5
- 所以 MAXR 5 是固定的（数字小了会报错）（但是大了不会）

- `QUA1 5`    **重点**

- *角度求积*
- 什么意思：跟踪要发很多方向不同的射线。QUA1 就是"发多少种角度"。
	- QUA1 5 = 用 5 个不同的角度去扫

	- QUA1 10 = 10 个角度
-**角度越多，覆盖越全面，碰撞概率算得越准，但也越慢。**
> 鱼和熊掌不可兼得嘛，和 精度宽度 不可同时有一个道理

- 因为 1D 圆柱几何是径向对称的，中子沿各方向飞的概率不同，但所有方向加权的总和要对。QUA1 5 是常用的基础值，够用。
- 建议：初学者用 5～8 就够。

> 解释一个这个模块吐出的盒子： TRACKING 装了啥

| 装的量 | 什么时候用 |
| --- | --- |
| 体积：每个区域有多大 | FLU: 后面要用它做通量归一化。 |
| 表面积：每个区域的外表面多大 | 碰撞概率矩阵的对角项要用它。|
| 弦长：一条射线穿过某个区域，走了多远 | ASM: 算碰撞概率的核心。 |
| 角度权重：每个方向的重要程度 | 求和的时候要用。 |

> 所以后面会看到 TRACK 被多个模块重复使用，都是在从这四样东西里各取所需。

**PLUS**
*边界条件对跟踪的影响*
- 如果几何是 R+ REFL，SYBILT: 扫描的时候知道"中子到边界会弹回来"，所以它只扫半个周期就够了。

- 如果几何是 R+ VOID，SYBILT: 要扫描中子从内部飞出去的所有路径，因为飞出去就没了，不会反射回来。

- 所以同样一个几何，边界条件改了，跟踪也得重新做。 后面 EVO: 燃耗计算里，如果只是材料变了、形状没变，跟踪可以复用——因为边界条件没变。
