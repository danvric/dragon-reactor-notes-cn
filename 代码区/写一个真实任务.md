# 真实工程计算
> 真实工程 vs 之前学的宏观截面玩具：
> 1. 不手写 SCAT，直接从核数据库读（`LIB:` 路线）。
> 2. CANDU 栅元是"管里套棒束"，必须用 2D 几何 + `CLUSTER`。
> 3. 必须做共振自屏蔽（`SHI:`），否则 U238 吸收算错，keff 直接崩。
> 4. **代码文件里绝对不能有中文**，CLE-2000 解析器只认 ASCII。
> 5. **代码文件必须是 Linux 换行（LF），不能是 Windows 换行（CRLF）**。

---

## 一、`LIB:` —— 从核数据库读材料
e.g.（读 DRAGLIB 格式，核素名与库里完全一致）
```text
LIBRARY := LIB: ::
    NMIX 4 CTRA WIMS
    MIXS LIB: DRAGON FIL: dlib99
    MIX 1 900.0
        U235 = U235 7.39E-4 1
        U238 = U238 2.17E-2 1
        O16  = O16  4.49E-2
    MIX 2 600.0
        Zr91 = Zr91 4.3E-2 1
    MIX 3 600.0
        H1   = H1   4.7E-2
        O16  = O16  2.3E-2
    MIX 4 600.0
        H1   = H1   4.7E-2
        O16  = O16  2.3E-2
    ;
```

逐项解释
- `MIXS LIB: DRAGON FIL: dlib99`：告诉程序"去叫 dlib99 那个 DRAGLIB 文件找截面"。
  - 若库是 WIMSD4 格式，写 `LIB: WIMSD4 FIL: iaea`。
  - 若库是 APOLIB-2 格式，写 `LIB: APLIB2 FIL: 文件名`。
- `MIX 1 900.0`：第 1 种材料，温度 900 K。
- `U235 = U235 7.39E-4 1`：
  - 左边是你在当前算例里用的别名；右边是库里的真实名字。
  - `7.39E-4` 是原子密度，单位是 $10^{24}\ \mathrm{cm^{-3}}$（不是 g/cm³，不是质量分数！）。
  - 末尾的 `1` 是共振区域编号，写了才会被 `SHI:` 识别为共振核素。**必须写！**
  - 轻核（H1、O16）通常不做自屏蔽，末尾不加 1。

**坑 1：核素名字必须与库里一致**
若报错 `Isotope not found`，跑：
```bash
strings /root/dlib99 | grep -i "u235"
```
输出什么名字，代码里就写什么名字。常见变体：U235、U-235、'2235'、92235。

**坑 2：温度必须在库里有数据**
DRAGLIB 一般只在若干固定温度点有数据（如 293.6 K、600 K、900 K）。报 `Temperature not found` 就换一个。

**坑 3：密度不能瞎填**
密度单位是 $10^{24}\ \mathrm{cm^{-3}}$。填 1.0 等于把燃料压成超密物质，keff 会飞到 2 以上。真实值参考上表。

**坑 4：NMIX 必须 ≥ 实际用到的 MIX 号**
`NMIX 4` 说明最多 4 种材料。后面 `GEO:` 里若出现 `MIX 5`，会报 `"mixtures in tracking greater than internal library"`。

## 二、`SHI:` —— 共振自屏蔽
为什么必须加：U238 的微观截面在共振区有尖锐峰，均匀摊开算会严重高估吸收。`SHI:` 修正它。

e.g.
```text
LIBRARY := SHI: LIBRARY TRACK TRKFIL ::
    EDIT 0 NOLJ ;
```

**坑 1：TRKFIL 必须传**
SHI: 需要扫描文件。若不写 TRKFIL，报错：
```text
EXCELP: Tracking file required unless NXT: tracking provided
```

**坑 2：TRKFIL 必须在 EXCELT: 里生成**
```text
TRACK TRKFIL := EXCELT: CANDU ::
```
左边必须有 `TRKFIL`，否则生成不了扫描文件。

**坑 3：TRKFIL 必须在开头声明**
```text
SEQ_BINARY TRKFIL ;
```

**坑 4：核素没标共振标记会报 "NO RESONANT ISOTOPES"**
`LIB:` 里核素密度后面不加 1，`SHI:` 就无法识别它需要自屏蔽，直接跳过。

## 三、EXCELT: —— 扫描
有 CLUSTER（棒束）时必须用 `EXCELT:`（或 `NXT:`），不能用 `SYBILT:`。

e.g.
```text
TRACK TRKFIL := EXCELT: CANDU ::
    TITLE 'CANDU Cell'
    EDIT 1 MAXR 200
    ALLG BATCH 100
    TRAK TISO 7 20.0 ;
```
`TISO 7 20.0`：7 个方向，每厘米 20 条射线。可调。
有对称边界（DIAG/SYME/SSYM）时，加 `SYMM 4` 之类参数，先不加也行。

**坑：EXCELT: 必须吐出 TRKFIL**
`TRACK TRKFIL := EXCELT: ...` 左边必须同时写 TRACK 和 TRKFIL。只写 TRACK 会报 `NO SEQUENTIAL BINARY TRACKING FILE YET DEFINED`。

## 四、ASM: 和 FLU: —— 必须也吃 TRKFIL
```text
PIJ  := ASM: LIBRARY TRACK TRKFIL :: PIJ ;
FLUX := FLU: PIJ LIBRARY TRACK TRKFIL :: TYPE K ;
```
TRKFIL 少传一个，就会报 `"Tracking file required"`。

## 五、完整流程顺序
```text
LIB:  →  GEO:  →  EXCELT:  →  SHI:  →  ASM:  →  FLU:  →  EDI:
```
每一步的输出作为下一步的输入，少一步直接报错。

## 六、环境和文件层面的坑（最容易崩在这里）
**坑 1：库文件路径不能太长**
DRAGON 底层的 Fortran 变量有长度上限（~16 字符），
`/mnt/e/Programming/Ubuntu22/Version5.0/Dragon/draglibendfb7r1Apolib99_v5p1`
这种超长路径会被截断成 `/mnt/e/Progr`，直接打不开。

解决办法：把库放到极短路径下，比如 `/root/dlib99`：
```bash
cp draglibendfb7r1Apolib99_v5p1 /root/dlib99
```
代码里写：
```text
MIXS LIB: DRAGON FIL: /root/dlib99
```

**坑 2：代码文件不能有中文**
CLE-2000 解析器只认 ASCII。日志里出现一堆 `? |8M` 就是读到了中文字节。

**坑 3：代码文件必须是 Linux 换行（LF）**
Windows 编辑器保存的是 CRLF，DRAGON 读到 `\r` 会报错。
用 nano 在 WSL 里写，或者跑：
```bash
tr -d '\r' < candu_cell.x2m > candu_cell_clean.x2m
```

**坑 4：默认 rdragon 会切到 /tmp/rundir1**
它会把代码和 data/ 里的东西一起复制到临时目录跑。
用 `-w` 参数能保留 debug 输出，但仍会去 `/tmp/rundir1`。
所以要么用绝对路径（短），要么把代码和库都放进 data/，用相对文件名。

## 七、常见报错速查
| 报错关键字 | 原因 | 解决 |
| ---- | ---- | ---- |
| ERROR NUMBER (59) + ? | 文件里有中文/CRLF/非法字符 | 纯英文 + `tr -d '\r'` |
| XSM FILE ... DOESNT EXIST | 路径写错或被截断 | 用短路径（/root/dlib99）或放进 data/ |
| Isotope ... not found | 核素名与库里不一致 | `strings 库名 | grep -i 核素名` 查真实名字 |
| Temperature ... not found | 库里没有该温度的数据 | 改成 293.6 / 600 / 900 再试 |
| NO RESONANT ISOTOPES | 核素密度后没加共振标记 1 | 补 1 |
| mixtures in tracking greater than internal library | GEO 里用了 NMIX 之外的材料号 | 检查 MIX 列表，或加大 NMIX |
| NO SEQUENTIAL BINARY TRACKING FILE | EXCELT: 没吐出 TRKFIL | `TRACK TRKFIL := EXCELT: ...` |
| Tracking file required | SHI/ASM/FLU 没传 TRKFIL | 三处调用都加上 TRKFIL |
| normal end of execution | 成功！ | 去查 KEFF= |

## 八、验证成功
跑完后，日志最后应出现：
```text
normal end of execution for dragon 5  Version 5.0.12
```
以及：
```text
++ TRACKING CALLED= ... FINAL KEFF= 1.XXXXXX
```
用 grep 抓：
```bash
grep "FINAL KEFF=" candu_cell.result
```
keff 落在 0.9 ~ 1.2 之间 = 物理合理；超出这个范围基本是密度/温度/核素名出了问题。
